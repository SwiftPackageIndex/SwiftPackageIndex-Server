You can read about all the changes in Swift 6.4 in the [announcement post](https://www.swift.org/blog/swift-6.4-released/), but there’s one feature that’s worth covering here in more detail as it might affect package compatibility. This release of Swift changes the default SwiftPM build system to use [Swift Build](https://swiftpackageindex.com/swiftlang/swift-build), meaning all of our 6.4 data comes from that build system.

One of the primary goals of the new build system is to make package builds more consistent across *all* of Swift’s supported platforms, which should mean you see fewer platform-specific surprises as a package author.

You shouldn’t see significant compatibility regressions caused by the new build system, but with over 12,000 packages in the index, it’s possible there will be issues that didn’t show up in testing. If any of your packages show failures against Swift 6.4, the quickest way to rule out the build system as the cause is to build them locally using the old build system:

```
swift build --build-system native
```

If your package builds with `--build-system native` but fails without it, check the list of known issues in the [SwiftPM 6.4 release notes](https://docs.swift.org/latest/documentation/packagemanagerdocs/6.4/). If your problem isn’t listed there, please [report it](https://github.com/swiftlang/swift-package-manager/issues) to the SwiftPM team.

The new build system also includes a couple of other changes that are worth looking out for in this release:

* An executable product and a library product whose names differ only by case are no longer supported.
* Build products generated by SwiftPM have moved. If your scripts rely on build artifact locations, get updated paths with `swift build --show-bin-path`.

Thanks in advance for any bug reports you submit after checking the compatibility of your packages, and enjoy Swift 6.4!
